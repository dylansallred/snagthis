B · Updates install themselves when you’re done

Downloads silently, then installs the next time SnagThis quits, or on macOS when its window has been closed and nothing has downloaded for 10 minutes. A neutral chip says 1.1.0 · installs when you quit, with an optional Restart now. After relaunch a fading Updated to 1.1.0 toast. Zero clicks in the common path.

Behaviour

  • Idle or busy: nothing to click. Never installs while a download is active; quitting still shows today’s “downloads in progress” prompt, with one added line saying the update installs as it quits.
  • macOS background install: window closed + no active download + no pending pairing request for 10 min → install silently and relaunch without a window, so Chrome can keep sending videos.
  • Later / defer: removed; the whole design is “later”. Restart now is the only action.
  • Failures: an install that didn’t finish is detected on the next launch (install-state file) and shows the amber chip + friendly popover with Download installer ↗ and Try again.
  • /Applications: unsupported copies show no chip; Settings explains and offers Move to Applications.

Code changes

  • main.js: in before-quit, when phase === 'downloaded' and the quit is confirmed, call quitAndInstall(true, false) ourselves (silent, don’t reopen), rather than setting autoInstallOnAppQuit. The code comment warns that flag breaks MacUpdater’s update-downloaded wait.
  • A background timer (window hidden + no blocking downloads for 10 min) calls quitAndInstall(true, true); install state gets reopenHidden, and bootstrap then creates the window hidden.
  • Remove both OS notifications, the reminder/Later IPC and timers, and the installWhenIdle checkbox (the idle install replaces it).
  • Renderer: chip kinds quiet / restarting / failed; small popover; UpdateSheet removed; updater:updated → toast.
  • Settings: hint 1.1.0 installs when you quit with Restart now; Check now answers inline.

Risks

  • macOS quit path: Squirrel.Mac must have staged the update before the quit; if it hasn’t, quitAndInstall waits for the native event and the quit hangs. Needs a timeout that falls back to a plain quit (the update then installs next time).
  • Mac users rarely quit (the app lives in the background), so most installs use the 10-minute background path: a silent restart the person never sees. Chrome requests during those ~5 s fail, so the extension should retry quietly.
  • Windows: NSIS installs silently on quit; a UAC prompt would appear only for per-machine installs.
  • The update lands “sometime later”: harder for support to know which version someone runs (Settings shows it).
