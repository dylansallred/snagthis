C · SnagThis updates itself when you step away

Downloads silently and installs by itself when it’s safe: nothing downloading and the window not in use for 5 minutes (unfocused or closed). If the window is on screen, a 10-second toast counts down Restarting to update… Cancel. Nothing appears until then. Zero clicks, and the only chip is the one Cancel leaves behind.

Behaviour

  • Safe moment (all true for 5 min): no blocking download, SnagThis not focused or its window closed, no dialog, sheet, paste or pairing request open, and no request from Chrome in the last 2 min.
  • Window visible but unfocused: 10 s countdown toast with Cancel, then a restart that reopens behind the current app (showInactive). Window closed: restart silently and stay hidden.
  • Cancel / defer: Cancel leaves the 1.1.0 · Restart chip for a manual install and skips auto-install for 4 h; quitting also installs (B’s path).
  • Never idle? If no safe moment comes within 3 days, the chip appears anyway, still without notifications.
  • Failures / Applications: same amber chip + friendly popover as A and B; unsupported copies never auto-install and Settings offers Move to Applications.

Code changes

  • main.js: generalise watchInstallWhenIdle into an always-on “safe moment” watcher: hasUpdateBlockingDownloads(), mainWindow.isFocused() / isVisible(), powerMonitor.getSystemIdleTime(), a pending-pairing flag and the last bridge request time. Send updater:countdown; the renderer answers Cancel over IPC.
  • Install state gets reopenHidden / reopenInactive, so bootstrap restores the window the way it was.
  • Remove both notifications, Later/reminders, the Install-when-downloads-finish checkbox and UpdateSheet; add updater:updated → toast.
  • Renderer: countdown toast (10 pixel pips), UpdateChip only for restart (after Cancel) and failed; popover for errors.
  • Settings: new switch Install updates automatically (default on) beside Check automatically; row hint Installs next time SnagThis is idle.

Risks

  • Surprise restarts: the most automatic option, and the hardest to trust. A person back at the window mid-countdown must be able to cancel with any key or click.
  • Chrome handoff: a video sent during the ~5 s restart hits a closed bridge; the extension must queue and retry, not show “SnagThis isn’t open”.
  • “Idle” is guesswork: watching a video in another app counts as unfocused. The 2-min bridge quiet period and download check cover SnagThis’s own work.
  • Same macOS Squirrel staging caveat as B: quitAndInstall needs the native download staged, so the watcher waits for it.
  • Most code: new watcher, window restore modes, extension retry.
